# Localize window layout functions and collapse dispatch

## PRD

[2026-05-31-remove-vestigial-customization](../prd.md)

## What to build

Fix the data model that forced the two-branch dispatch (see the PRD's "Follow-up:
localize layout functions" section). The ~12 window-layout functions are currently
monkey-patched onto the `hs.window` module table (`function hs.window.left(win)
...`); that single choice produces the LuaLS `inject-field` warnings, the
two-table dispatch asymmetry, and the string-keyed lookup.

The clean refactor:

- Define the ~12 layout functions as plain `local function`s, with their geometry
  bodies copied **verbatim** — only the binding mechanism changes, not the math.
- Have the `mappings` array hold **direct function references** instead of name
  strings.
- Wrap native `maximize` uniformly as `function(w) w:maximize() end`, so every
  mapping entry is a function taking a window.
- Reduce the dispatch to the single branch-free call:

  ```lua
  mapping.fn(hs.window.focusedWindow())
  ```

  No monkey-patch, no string lookup, no two-branch dispatch, no `hs.window`
  namespace pollution.

Companion cleanups:

- **`.luacheckrc`:** retarget the `files['hammerspoon/windows.lua']` carve-out so
  it covers only the legitimate `hs.window.animationDuration = 0` write, and update
  its comment. Do not blanket-delete it; the monkey-patch-era purpose is gone but
  the real-API write still needs an allowance.
- **`windows.lua` header comment:** correct or remove the stale claim of a "LuaLS
  carve-out" in `.vscode/settings.json` that does not exist.

Behavior-preserving: all 17 keys → identical geometry. The dispatch change is the
one behavior the spec suite structurally cannot cover, so it is gated on the live
verification below.

- [x] The dispatch is the single branch-free expression
      `mapping.fn(hs.window.focusedWindow())`.

      injected onto `hs.window`).

      `hs.window.animationDuration` write, with its comment updated; the
      monkey-patch-era allowance is no longer implied.
- [x] The stale "LuaLS carve-out" claim in the `windows.lua` header comment is
      corrected or removed.

      arrows / shift-rows / quarter keys (`u` `i` `o` `m`) / `space` behaves
      identically to before, with special attention to `return` → maximize.
