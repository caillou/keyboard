# Collapse window bindings into windows.lua

## PRD

[2026-05-31-remove-vestigial-customization](../prd.md)

## What to build

Make `windows.lua` the single source of truth for the window layout mode, with no
override mechanism and no dead branches. The window bindings — `modifiers`,
`trigger`, and the `mappings` array — move inline as plain locals, declared
directly in `windows.lua`. The `windows-bindings-defaults.lua` file is deleted,
along with the `pcall(require, "keyboard.windows-bindings")` try/fallback block
that always failed.

Two further collapses, all behavior-preserving:

- Drop the hard-coded `showHelp` flag and the entire `if showHelp == true then ...
  end` help-text rendering loop (including the now-unused `hotKeyStr` branch).
  **Keep** `getModifiersStr` and use it to compute the modal title from the
  inlined `modifiers`/`trigger` locals, so changing the trigger stays a one-line
  edit and the two `hs.hotkey` binds and the title share one source.
- Replace the two-branch window-key dispatch with a single expression:

  ```lua
  hs.window[winFunction](hs.window.focusedWindow())
  ```

  The `else` branch (`fw[winFunction](fw)`) never fired: every mapped function —
  custom layouts assigned onto `hs.window` and native `maximize` — resolves off
  the `hs.window` table.

Runtime behavior is unchanged: same keys → same window layouts, same modal title.
The dispatch collapse is the one change the spec suite structurally cannot cover,
so it is gated on the live verification below.

## Acceptance criteria

- [ ] `modifiers = { "ctrl" }`, `trigger = "s"`, and the full `mappings` array are
      declared as plain locals inside `windows.lua` (same keys → same window
      functions, unchanged).
- [ ] `hammerspoon/windows-bindings-defaults.lua` is deleted and the
      `pcall(require, "keyboard.windows-bindings")` fallback block is gone.
- [ ] The `showHelp` flag and the `if showHelp == true then ... end` help loop
      (with the `hotKeyStr` branch) are removed; `getModifiersStr` remains and
      builds the modal title from the inlined `modifiers`/`trigger`.
- [ ] The window-key dispatch is the single expression
      `hs.window[winFunction](hs.window.focusedWindow())`.
- [ ] `make test`, `make lint`, and `make fmt-check` are green.
- [ ] **Live verification (human, cannot be automated):** after `hs -c
      "hs.reload()"`, `Ctrl+s` then `return` maximizes (native function), and
      `Ctrl+s` then a custom layout key (`j`/`l`) moves the window correctly.
