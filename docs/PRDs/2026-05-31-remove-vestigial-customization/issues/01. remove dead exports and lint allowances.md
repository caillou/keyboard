# Remove dead exports and lint allowances

## PRD

[2026-05-31-remove-vestigial-customization](../prd.md)

## What to build

Strip the zero-caller exports the upstream customization lineage left behind, so
each module's public surface matches what the config actually uses. All four are
removals verified to have no callers across `hammerspoon/` and `spec/`:

- `init.lua`: remove the `keyUpDown` global and the
  `enableHotkeyForWindowsMatchingFilter` global.
- `.luacheckrc`: remove `keyUpDown` and `enableHotkeyForWindowsMatchingFilter`
  from the `globals` list and update the surrounding comment so it no longer
  describes them. **Keep** `configWatcher` and `keyboardWatcher` — the
  pathwatchers must stay global or they get garbage-collected.
- `space-fn.lua`: remove `M.log = log` (the Adapter's own local `log` stays for
  internal use) and the unused `M.stop()` function. `M.start` and `M.setEnabled`
  remain.
- `status-message.lua`: remove the `notify` method. `show` and `hide` remain —
  the only methods `windows.lua` calls.

Behavior-preserving: the removed names have no callers, so runtime and the
space-fn layer are untouched. Correctness is established by the gates.
